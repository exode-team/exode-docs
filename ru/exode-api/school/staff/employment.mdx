<Info>
    Трудоустройство (`employment`) связывает пользователя школы с департаментом и, опционально, должностью.
    У сотрудника может быть несколько записей трудоустройства в истории, но только **одна активная** для
    конкретной пары департамент + должность. Должность можно не указывать — тогда сотрудник числится в
    департаменте **без должности**, и активная запись такого типа уникальна по паре департамент + пользователь.
    У записи также фиксируются условия занятости: вид (`kind`), тип (`type`) и ставка (`rate`).
</Info>

<Warning>
    Все эндпоинты модуля staff доступны **только** для школ сегмента `Corporate`. Для остальных сегментов запрос
    вернёт `401` с `cause: "Forbidden"` и сообщением `Allowed only for Corporate school`.
</Warning>

<Warning>
    Если в школе подключено приложение — источник оргструктуры (например, интеграция с Verifix) и оно импортирует
    сотрудников, трудоустройствами с `extId` управляет оно, и изменение таких записей через API вернёт
    `MiniappInstallationManagedEntity` (в `data.installationId` — ID установки приложения). Ограничение действует
    для `hire` с `extId` в теле (пространство `extId` принадлежит интеграции), для `transfer` и `terminate` записи
    с `extId`, для `update` записи с `extId`, если меняется дата начала `startAt` (ставку, тип и вид занятости
    интеграция не синхронизирует — их менять можно), а также для `promote` записи с `extId`, если меняется
    должность (или грейд — когда интеграция синхронизирует грейды). Записи без `extId` по-прежнему можно менять
    через API. Если импорт сотрудников в настройках приложения выключен, ограничение снимается: записи остаются
    связанными с интеграцией, но меняются вручную.
</Warning>

<Info>
    Помимо должности, трудоустройству можно присвоить [грейд](/ru/exode-api/school/staff/grade) (`gradeId`) —
    уровень карьерной шкалы школы. Грейд доступен, когда грейды включены в школе, иначе вернётся
    `StaffGradesDisabled`. Если у должности задан ограниченный список грейдов, присвоить можно только грейд из
    этого списка (`StaffGradeNotForPosition`). Если [должность привязана к подразделениям](/ru/exode-api/school/staff/position),
    назначить её можно только в одном из них (`StaffPositionNotInDepartment`); должность без привязки — общая для
    всей школы и доступна в любом департаменте.
</Info>

<Info>
    Перевод (`transfer`) и повышение (`promote`) не изменяют текущую запись, а **закрывают** её (`finishAt`, статус
    `Terminated`) и создают **новую** активную запись в целевом департаменте либо с новой должностью. Условия
    занятости (`kind`, `type`, `rate`) и внешний идентификатор `extId` переносятся в новую запись без изменений.
    В ответе возвращается именно новая запись трудоустройства — **с новым `id`**. Поэтому в своей системе храните
    `extId` трудоустройства, а не `id`: `id` меняется при каждом переводе и повышении, `extId` — нет. Назначение
    руководителем департамента переходит на новую запись автоматически; ранее созданные отсутствия остаются
    привязанными к закрытой записи. Исправить условия занятости или дату начала текущей записи без перехода
    можно через [`update`](#изменить-условия-трудоустройства) — тогда запись и её `id` не меняются.
</Info>

<Info>
    У трудоустройства может быть внешний идентификатор `extId` — ID записи в системе клиента (например, HR-системе).
    От 1 до 50 символов, без `/` и пробелов. Уникален в рамках школы **среди открытых (не завершённых)**
    трудоустройств: при переводе или повышении `extId` переносится на новую активную запись (закрытая сохраняет
    копию), а после увольнения освобождается — его можно снова передать при повторном найме. По `extId` доступны
    отдельные роуты `ext/{extId}/update`, `ext/{extId}/transfer`, `ext/{extId}/promote` и `ext/{extId}/terminate`;
    они находят только открытую запись, поэтому для уже закрытого трудоустройства вернут `StaffEmploymentNotFound`.
</Info>

### Какую операцию выбрать

| Событие в HR-системе | Операция |
|---|---|
| Приём на работу, новое совместительство | [`hire`](#нанять-сотрудника) — создаёт ещё одну активную запись |
| Исправление даты приёма, ставки, типа или вида занятости (без перевода) | [`update`](#изменить-условия-трудоустройства) — меняет текущую запись, без истории |
| Перевод в другой департамент (должность та же) | [`transfer`](#перевести-в-другой-департамент) |
| Смена должности и/или грейда в том же департаменте | [`promote`](#сменить-должность) |
| Сменились и департамент, и должность (или грейд) | [`transfer`](#перевести-в-другой-департамент) с `toPositionId` / `toGradeId` — одной операцией |
| Увольнение с одного места работы | [`terminate`](#уволить-сотрудника) |

Удаления трудоустройства в API нет: запись закрывается только через `terminate` и остаётся в истории. Каждая
операция изменения есть в двух вариантах: по `employmentId` (в теле запроса, у `update` — в пути) и по `extId`
в пути (`ext/{extId}/...`). Работают они одинаково; вариант с `extId` удобнее при синхронизации — не нужно
хранить внутренние ID Exode.

## Список трудоустройств

```
GET /saas/v2/staff/employment/list
```

Требуется аутентификация и право [**«Просмотр персонала»**](/ru/exode-api/permissions) (`StaffView`).

<ParamField query="statuses" type="enum[]" required={false}>
    Фильтр по статусам трудоустройства. Возможные значения: `Active`, `Terminated`. До 250 значений.

    записи, используйте `statuses=Active`.
</ParamField>

<ParamField query="search" type="string" required={false}>
    Поиск по сотруднику: ФИО, логин, ID пользователя. Максимум 50 символов.
</ParamField>

#### Сортировка

<ParamField query="createdAt" type="enum" required={false}>

## Нанять сотрудника

```
POST /saas/v2/staff/employment/hire
```

Требуется аутентификация и право **«Управление персоналом»** (`StaffManage`).

Создаёт новую активную запись трудоустройства. Пользователь, департамент и должность (если указана) должны
принадлежать школе. У сотрудника не может быть активного дубля с той же парой департамент + должность, а при
найме без должности — с той же парой департамент + пользователь. Если пользователь ранее был уволен и имеет
статус `Terminated`, найм автоматически возвращает ему статус `Active`.

Департамент **обязателен** и указывается по ID или внешнему идентификатору: в паре `departmentId` /
`departmentExtId` передаётся ровно один параметр. Должность **опциональна**: передайте ровно один параметр из
пары `positionId` / `positionExtId`, либо не передавайте оба — тогда сотрудник нанимается без должности. Оба
поля одной пары одновременно передавать нельзя. Если должность привязана к подразделениям, департамент найма
должен быть среди них, иначе вернётся `StaffPositionNotInDepartment`.

Грейд **опционален** и задаётся так же — одним параметром из пары `gradeId` / `gradeExtId`. Он проверяется на
принадлежность школе (`StaffGradeNotFound`) и на соответствие списку грейдов должности
(`StaffGradeNotForPosition`); при выключенных в школе грейдах вернётся `StaffGradesDisabled`.

### Параметры запроса

<ParamField body="userId" type="integer" required>
    ID пользователя, который принимается на работу. Пользователь должен быть уже зарегистрирован в школе, иначе
    вернётся `UserNotBelongsToSchool`. ID возвращается при создании пользователя; по вашему внешнему
    идентификатору его можно найти через [`user/find`](/ru/exode-api/school/user/find). Чтобы создать пользователя
    и сразу нанять его одним вызовом, используйте `extra.staff.employments` в
    [`user/create`](/ru/exode-api/school/user/create) или [`user/upsert`](/ru/exode-api/school/user/upsert).
</ParamField>

<ParamField body="extId" type="string" required={false}>
    Внешний идентификатор трудоустройства из системы клиента. От 1 до 50 символов, без `/` и пробелов.
    Должен быть уникален в рамках школы среди открытых (не завершённых) трудоустройств. Задаётся только при найме:
    `update` трудоустройства `extId` не меняет, а в панели администратора такого поля нет. Если в школе подключено
    приложение — источник оргструктуры и оно импортирует сотрудников, найм с `extId` вернёт
    `MiniappInstallationManagedEntity`.
</ParamField>

<ParamField body="positionId" type="integer" required={false}>
    ID должности. Должность должна принадлежать школе и быть доступна в департаменте найма (должность без
    привязки к подразделениям доступна везде). Опционально: передайте один параметр из пары
    `positionId` / `positionExtId`, либо не передавайте оба — сотрудник будет нанят без должности.
</ParamField>

<ParamField body="positionExtId" type="string" required={false}>
    Внешний идентификатор (`extId`) должности — альтернатива `positionId`.
</ParamField>

<ParamField body="gradeId" type="integer" required={false}>
    ID [грейда](/ru/exode-api/school/staff/grade). Грейд должен принадлежать школе и входить в список грейдов
    должности (если список задан). Опционально: передайте один параметр из пары `gradeId` / `gradeExtId`, либо не
    передавайте оба — сотрудник будет нанят без грейда.
</ParamField>

<ParamField body="gradeExtId" type="string" required={false}>
    Внешний идентификатор (`extId`) грейда — альтернатива `gradeId`.
</ParamField>

<ParamField body="departmentId" type="integer" required={false}>
    ID департамента. Департамент должен принадлежать школе. Передаётся ровно один параметр из пары
    `departmentId` / `departmentExtId`.
</ParamField>

<ParamField body="departmentExtId" type="string" required={false}>
    Внешний идентификатор (`extId`) департамента — альтернатива `departmentId`.
</ParamField>

<ParamField body="startAt" type="string" required={false}>
    Дата начала трудоустройства в формате ISO 8601 (например, `2026-07-02T00:00:00.000Z`). По умолчанию — текущий
    момент. Можно указать дату в прошлом (перенос истории) или в будущем (запланированный приём): будущая запись
    сразу получает статус `Active`, но до наступления `startAt` не попадает в выборку `activeOnly=true` и не может
    быть назначена руководителем департамента.
</ParamField>

<ParamField body="kind" type="enum" required={false}>
    Вид занятости: `Main` (основное место работы), `InternalSecondary` (внутреннее совместительство),
    `ExternalSecondary` (внешнее совместительство). По умолчанию `Main`.
</ParamField>

<ParamField body="type" type="enum" required={false}>
    Тип занятости: `FullTime` (полная) или `PartTime` (частичная). По умолчанию `FullTime`.
</ParamField>

## Изменить условия трудоустройства

```
PUT /saas/v2/staff/employment/{employmentId}/update
```

Требуется аутентификация и право **«Управление персоналом»** (`StaffManage`).

Исправляет условия **открытой** записи трудоустройства на месте — без перехода и без новой записи в истории:
дату начала (`startAt`), ставку (`rate`), тип (`type`) и вид (`kind`) занятости. `id` и `extId` записи не
меняются. Подходит, чтобы исправить ошибку ввода или изменить ставку без перевода. Департамент, должность и
грейд так не меняются — для них есть [`transfer`](#перевести-в-другой-департамент) и
[`promote`](#сменить-должность), которые сохраняют историю.

Передаются только изменяемые поля; не переданные (и `null`) остаются прежними. Если не передано ни одного поля,
вернётся `StaffEmploymentInputRequired`. Для закрытой записи вернётся `StaffEmploymentNotFound`.

<Info>
    Если запись создана переводом или повышением, вместе с её `startAt` переносится дата окончания (`finishAt`)
    предыдущей записи цепочки — история остаётся непрерывной. Новая дата начала не может быть раньше начала
    предыдущей записи, иначе вернётся `StaffEmploymentInvalidTransitionDate`. У записи, созданной наймом, дату
    начала можно перенести на любую — в прошлое или в будущее.
</Info>

### Параметры запроса

<ParamField path="employmentId" type="integer" required>
    ID открытой записи трудоустройства.
</ParamField>

<ParamField body="startAt" type="string" required={false}>
    Новая дата начала трудоустройства в формате ISO 8601 (например, `2026-07-01T00:00:00.000Z`). Если в школе
    подключено приложение — источник оргструктуры и оно импортирует сотрудников, изменение даты начала записи с
    `extId` вернёт `MiniappInstallationManagedEntity`.
</ParamField>

<ParamField body="kind" type="enum" required={false}>
    Вид занятости: `Main` (основное место работы), `InternalSecondary` (внутреннее совместительство),
    `ExternalSecondary` (внешнее совместительство).
</ParamField>

<ParamField body="type" type="enum" required={false}>
    Тип занятости: `FullTime` (полная) или `PartTime` (частичная).
</ParamField>

<ParamField body="rate" type="number" required={false}>

## Перевести в другой департамент

```
POST /saas/v2/staff/employment/transfer
```

Требуется аутентификация и право **«Управление персоналом»** (`StaffManage`).

Закрывает текущую активную запись трудоустройства (`finishAt`, статус `Terminated`) и создаёт **новую** активную
запись в целевом департаменте. Целевой департамент должен принадлежать школе. Если у сотрудника в целевом
департаменте уже есть открытая запись с той же должностью, вернётся `StaffEmploymentAlreadyExists`.

По умолчанию должность и грейд сохраняются; если текущая должность привязана к подразделениям и целевого
департамента среди них нет, вернётся `StaffPositionNotInDepartment`. Чтобы одновременно сменить должность и/или
грейд, передайте `toPositionId` и/или `toGradeId` — это одна операция вместо пары `transfer` + `promote`. Новые
должность и грейд проверяются так же, как при [смене должности](#сменить-должность), но относительно целевого
департамента.

### Параметры запроса

<ParamField body="employmentId" type="integer" required>
    ID переводимой активной записи трудоустройства.
</ParamField>

<ParamField body="toDepartmentId" type="integer" required={false}>
    ID целевого департамента. Департамент должен принадлежать школе. Передаётся ровно один параметр из пары
    `toDepartmentId` / `toDepartmentExtId`.
</ParamField>

<ParamField body="toDepartmentExtId" type="string" required={false}>
    Внешний идентификатор (`extId`) целевого департамента — альтернатива `toDepartmentId`.
</ParamField>

<ParamField body="toPositionId" type="integer | null" required={false}>
    ID новой должности в целевом департаменте. Значение `null` **снимает** должность. Не передан — должность
    сохраняется. Указывается только по ID (варианта с `extId` нет).
</ParamField>

<ParamField body="toGradeId" type="integer | null" required={false}>
    ID нового [грейда](/ru/exode-api/school/staff/grade). Значение `null` **снимает** грейд. Указывается только
    по ID (варианта с `extId` нет).
</ParamField>

<ParamField body="startAt" type="string" required={false}>
    Дата перевода в формате ISO 8601. Должна быть не раньше `startAt` текущей записи, иначе вернётся
    `StaffEmploymentInvalidTransitionDate`. По умолчанию — текущий момент.
</ParamField>

## Сменить должность

```
POST /saas/v2/staff/employment/promote
```

Требуется аутентификация и право **«Управление персоналом»** (`StaffManage`).

Закрывает текущую активную запись трудоустройства (`finishAt`, статус `Terminated`) и создаёт **новую** активную
запись с новой должностью и/или грейдом в том же департаменте. Целевая должность должна принадлежать школе и быть
доступна в текущем департаменте (`StaffPositionNotInDepartment`). Если у сотрудника в этом департаменте уже есть
открытая запись с новой должностью, вернётся `StaffEmploymentAlreadyExists`.

Запрос должен явно выражать намерение: передайте должность (`toPositionId` **или** `toPositionExtId`) и/или
грейд (`toGradeId` **или** `toGradeExtId`), чтобы назначить их, либо `null`, чтобы **снять** (сотрудник останется
в департаменте без должности или без грейда). Если не передать ни одно из этих полей, вернётся ошибка
`StaffEmploymentInputRequired`.

Грейд проверяется так же, как при найме: `StaffGradeNotFound`, `StaffGradeNotForPosition`,
`StaffGradesDisabled`. Если меняется только должность, текущий грейд сохраняется, когда он есть в списке грейдов
новой должности, и сбрасывается в `null`, когда его там нет.

</ParamField>

<ParamField body="toGradeId" type="integer | null" required={false}>

</ParamField>

<ParamField body="toGradeExtId" type="string" required={false}>

## Уволить сотрудника

```
POST /saas/v2/staff/employment/terminate
```

Требуется аутентификация и право **«Управление персоналом»** (`StaffManage`).

Закрывает активную запись трудоустройства: проставляет `finishAt`, переводит статус в `Terminated` и снимает
сотрудника с руководства департаментами. В ответе возвращается закрытая запись.

<Warning>
    Увольнение с **последнего активного** трудоустройства автоматически переводит пользователя в статус
    `Terminated` — доступ к платформе закрывается: вход запрещён, активные сессии завершаются. Повторный найм
    (`hire`) пользователя со статусом `Terminated` автоматически возвращает ему статус `Active`.
</Warning>

<Info>
    Защиты при увольнении с последнего активного трудоустройства: нельзя уволить самого себя — пользователя,
    от имени которого выполняется запрос (`StaffCannotTerminateSelf`), и владельца школы
    (`StaffCannotTerminateSchoolOwner`). При сверке полного списка сотрудников пропускайте этих пользователей.
</Info>

<Note>
    Увольнение вступает в силу в момент вызова: запись сразу получает статус `Terminated`, а при увольнении
    с последнего трудоустройства сразу закрывается доступ — даже если `finishAt` указан в будущем. Отложенного
    увольнения нет, поэтому вызывайте `terminate` в день фактического увольнения.
</Note>
