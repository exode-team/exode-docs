<Info>
  Должности — это справочник наименований позиций сотрудников школы (например, «Backend Engineer»). Должности
  назначаются сотрудникам при найме и повышении и используются модулем персонала (staff) для описания структуры
  занятости.
</Info>

<Warning>
  Все эндпоинты модуля персонала доступны **только для школ корпоративного сегмента** (`Corporate`).
  Запрос от школы другого сегмента будет отклонён.
</Warning>

## Требования к правам доступа

<Check>
  Чтение (`list`) требует права [**«Просмотр персонала»**](/ru/exode-api/permissions) (`StaffView`). Создание, обновление и удаление требуют права **«Управление персоналом»** (`StaffManage`).
  Во всех случаях необходима аутентификация по токену и принадлежность школы к сегменту `Corporate`.
</Check>

<Warning>
  Сервисный пользователь должен быть аутентифицирован по токену и иметь соответствующие права доступа к указанной
  школе.
</Warning>

<Info>
  Название должности **уникально в рамках школы** без учёта регистра («Менеджер» и «менеджер» — одно и то же
  название). Попытка создать или переименовать должность в уже существующее название в этой же школе вернёт
  ошибку `StaffPositionNameIsNotUniq`.
</Info>

<Info>
  Поле `extId` — внешний идентификатор должности из системы клиента (CRM/1C, например GUID). Уникален в рамках
  школы среди неудалённых записей (уникальный индекс `school + extId`). От 1 до 50 символов, не может содержать
  `/` и пробельные символы — значение используется в путях `ext/{extId}`.
</Info>

## Привязка к подразделениям и грейдам

Должность можно ограничить списком подразделений и списком грейдов. Обе привязки **необязательны**: создавать
должности без них можно, это ни на что не влияет, а привязать можно позже.

- **`departmentIds`** — подразделения, в которых доступна должность. Не переданы или пустой массив — должность
  **общая для всей школы** (в интерфейсе: «Все подразделения»). Если привязка задана, нанять, повысить или
  перевести сотрудника на эту должность в другом подразделении нельзя — вернётся `StaffPositionNotInDepartment`
  (см. [занятость](/ru/exode-api/school/staff/employment)).
- **`gradeIds`** — [грейды](/ru/exode-api/school/staff/grade), которые можно присвоить сотруднику на этой
  должности. Не переданы или пустой массив — подходят любые грейды школы.

<Info>
  Массив **заменяет список целиком**: чтобы добавить подразделение, передайте полный новый список. `[]` снимает
  привязку, а если поле не передано при обновлении — привязка не меняется. Передаются внутренние ID подразделений
  и грейдов (не `extId`): ID подразделения по его `extId` можно получить через
  [`department/list?extIds=...`](/ru/exode-api/school/staff/department). В ответе должности возвращается
  `departmentIds` — подразделения, к которым она привязана (`[]` — общая для школы); список должностей
  подразделения отдаёт `position/list?departmentId={id}`. Привязка к грейдам в ответе не возвращается — грейды
  должности отдаёт [`grade/list?positionId={id}`](/ru/exode-api/school/staff/grade). Удалённое подразделение
  снимается со всех должностей: должность, у которой не осталось подразделений, становится общей для школы.
</Info>

<Warning>
  Если в школе подключено приложение — источник оргструктуры (например, интеграция с Verifix) и оно импортирует
  должности, должности с `extId` управляются им: создание должности с `extId`, изменение `name` и `extId` такой
  должности и её удаление через API вернут ошибку `MiniappInstallationManagedEntity`. Привязку к подразделениям и
  грейдам (`departmentIds`, `gradeIds`) при этом менять можно. Если импорт должностей в настройках приложения
  выключен, ограничение снимается: должности остаются связанными с интеграцией, но меняются вручную.
</Warning>

## Список должностей

```
GET /saas/v2/staff/position/list
```

Требуется аутентификация и право **«Просмотр персонала»** (`StaffView`).

<Info>
  Эндпоинт возвращает пагинированный список должностей. Параметры пагинации и фильтрации передаются как
  query-параметры.
</Info>

### Параметры

<ParamField query="skip" type="integer" required={false}>
  Количество пропускаемых записей (offset-пагинация). Минимум `0`.
</ParamField>

<ParamField query="take" type="integer" required={false}>
  Количество возвращаемых записей на странице. От `1` до `1000`.
</ParamField>

<ParamField query="page" type="integer" required={false}>
  Номер страницы (альтернатива `skip`). Минимум `1`.
</ParamField>

<ParamField query="positionIds" type="integer[]" required={false}>
  Фильтр по ID должностей. До 250 значений.
</ParamField>

<ParamField query="search" type="string" required={false}>
  Поиск по названию должности. Максимум 50 символов. Поиск нечёткий (находит и частичные совпадения), поэтому для
  поиска конкретной должности по имени сравнивайте `name` найденных записей со своим значением без учёта
  регистра, а надёжнее — ищите по `extIds`.
</ParamField>

<ParamField query="extIds" type="string[]" required={false}>
  Фильтр по списку внешних идентификаторов (`extId`). До 250 значений, каждое — максимум 50 символов.
</ParamField>

<ParamField query="departmentId" type="integer" required={false}>
  Должности, доступные в подразделении: привязанные к нему и общие для всей школы (без привязки к
  подразделениям).
</ParamField>

<ParamField query="createdAt" type="enum" required={false}>
  Направление сортировки по дате создания. Возможные значения: `ASC`, `DESC`. Аналогично работают параметры `id`
  и `updatedAt`.
</ParamField>

### Ответ

<ResponseField name="payload" type="object" required>
  Пагинированный объект: `items` (массив должностей), `page`, `count`, `pages`, `isFirst`, `isLast`, `next`,
  `prev`.
</ResponseField>

```bash cURL

  --header 'Authorization: Bearer YOUR_TOKEN'
```

## Создание должности

```
POST /saas/v2/staff/position/create
```

Требуется аутентификация и право **«Управление персоналом»** (`StaffManage`).

### Параметры запроса

<ParamField body="name" type="string" required>
  Название должности. От 1 до 100 символов. Пробелы в начале и конце обрезаются автоматически. Должно быть
  уникальным в рамках школы.
</ParamField>

<ParamField body="extId" type="string" required={false}>
  Внешний идентификатор должности из системы клиента (CRM/1C). От 1 до 50 символов, не может содержать `/` и
  пробельные символы. Должен быть уникальным в рамках школы среди неудалённых записей.
</ParamField>

<ParamField body="departmentIds" type="integer[]" required={false}>
  ID подразделений, в которых доступна должность. До 250 значений. Не передано или `[]` — должность общая для всей
  школы. Все подразделения должны принадлежать школе, иначе вернётся `StaffDepartmentNotFound`. Подробнее — в
  разделе [«Привязка к подразделениям и грейдам»](#привязка-к-подразделениям-и-грейдам).
</ParamField>

<ParamField body="gradeIds" type="integer[]" required={false}>
  ID [грейдов](/ru/exode-api/school/staff/grade), которые можно присвоить сотруднику на этой должности. До 100
  значений. Не передано или `[]` — подходят любые грейды. Все грейды должны принадлежать школе, иначе вернётся
  `StaffGradeNotFound`.
</ParamField>

<RequestExample>
```bash cURL
curl --location 'https://api.exode.biz/saas/v2/staff/position/create' \
  --header 'Seller-Id: {{ sellerId }}' \
  --header 'School-Id: {{ schoolId }}' \

  --header 'Authorization: Bearer YOUR_TOKEN' \
```

```javascript Node.js
        'Content-Type': 'application/json',
        'Authorization': 'Bearer YOUR_TOKEN',

createPosition();
```

## Обновление должности

```
PUT /saas/v2/staff/position/{positionId}/update
```

Требуется аутентификация и право **«Управление персоналом»** (`StaffManage`).

### Параметры

<ParamField path="positionId" type="integer" required>
  ID обновляемой должности в рамках школы.
</ParamField>

<ParamField body="name" type="string" required={false}>
  Новое название должности. От 1 до 100 символов. Пробелы в начале и конце обрезаются автоматически. Должно быть
  уникальным в рамках школы.
</ParamField>

<ParamField body="extId" type="string" required={false}>
  Внешний идентификатор должности из системы клиента (CRM/1C). От 1 до 50 символов, не может содержать `/` и

## Обновление должности по extId

```
PUT /saas/v2/staff/position/ext/{extId}/update
```

Требуется аутентификация и право **«Управление персоналом»** (`StaffManage`).

<Info>
  Эндпоинт-аналог обновления по ID: должность находится по внешнему идентификатору `extId` в рамках школы.
  Значение `extId` в пути должно быть URL-encoded.
</Info>

### Параметры

<ParamField path="extId" type="string" required>
  Внешний идентификатор (`extId`) обновляемой должности в рамках школы. Должен быть URL-encoded.
</ParamField>

<ParamField body="name" type="string" required={false}>

</ParamField>

<ParamField body="extId" type="string" required={false}>
  Новый внешний идентификатор должности. От 1 до 50 символов, не может содержать `/` и пробельные символы.
  Должен быть уникальным в рамках школы среди неудалённых записей.
</ParamField>

<ParamField body="departmentIds" type="integer[]" required={false}>
  Новый список ID подразделений, в которых доступна должность (до 250). Работает так же, как при
  [обновлении по ID](#обновление-должности).
</ParamField>

<ParamField body="gradeIds" type="integer[]" required={false}>

## Удаление должности

```
DELETE /saas/v2/staff/position/{positionId}/delete
```

Требуется аутентификация и право **«Управление персоналом»** (`StaffManage`).
