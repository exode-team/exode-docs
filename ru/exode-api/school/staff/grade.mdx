<Info>
  Грейды — это уровни карьерной лестницы школы (например, Junior → Middle → Senior). Шкала грейдов одна на все
  должности школы. Грейд присваивается сотруднику при найме, повышении и переводе (см.
  [занятость](/ru/exode-api/school/staff/employment)) и используется для расчёта готовности к следующему грейду.
</Info>

<Warning>
  Все эндпоинты модуля персонала доступны **только для школ корпоративного сегмента** (`Corporate`).
  Запрос от школы другого сегмента будет отклонён.
</Warning>

## Требования к правам доступа

<Check>
  Чтение (`list`) требует права [**«Просмотр персонала»**](/ru/exode-api/permissions) (`StaffView`). Создание, обновление и удаление требуют права **«Управление персоналом»** (`StaffManage`).
  Во всех случаях необходима аутентификация по токену и принадлежность школы к сегменту `Corporate`.
</Check>

<Warning>
  Сервисный пользователь должен быть аутентифицирован по токену и иметь соответствующие права доступа к указанной
  школе.
</Warning>

## Как устроена шкала

<Info>
  **Порядок.** Поле `order` — место грейда на лестнице: чем больше `order`, тем выше грейд. Новый грейд создаётся
  на вершине шкалы. Порядок грейдов меняется в интерфейсе (**Школа → Структура → Грейды**, перетаскиванием строки);
  через REST API порядок не меняется. Список грейдов всегда возвращается от младшего к старшему.
</Info>

<Info>
  **Включение грейдов.** Грейды включаются в разделе **«Грейды»** в интерфейсе. Шкалу можно настроить заранее — через
  API или в интерфейсе, — но присвоить грейд сотруднику (`gradeId` в `hire`, `toGradeId` в `promote` и `transfer`)
  можно только после включения: иначе вернётся ошибка `StaffGradesDisabled`.
</Info>

<Info>
  **Грейды должности.** Должность может ограничить список подходящих ей грейдов — параметр `gradeIds` при
  [создании и обновлении должности](/ru/exode-api/school/staff/position). Если ограничение не задано, должности
  подходят любые грейды школы. Сотруднику можно присвоить только грейд своей должности, иначе вернётся
  `StaffGradeNotForPosition`.
</Info>

<Info>
  **Условия перехода.** Условия перехода на грейд (курсы, которые нужно пройти сотруднику на конкретной должности)
  настраиваются в интерфейсе. По ним считается готовность к следующему грейду — сотрудников, выполнивших все условия,
  можно получить фильтром `readyForPromotion` в [списке занятостей](/ru/exode-api/school/staff/employment).
</Info>

<Info>
  Название грейда **уникально в рамках школы** без учёта регистра («Senior» и «senior» — одно и то же название).
  Попытка создать или переименовать грейд в уже существующее название в этой же школе вернёт ошибку
  `StaffGradeNameIsNotUniq`.
</Info>

<Info>
  Поле `extId` — внешний идентификатор грейда из системы клиента (CRM/1C, например GUID). Уникален в рамках
  школы среди неудалённых записей. От 1 до 50 символов, не может содержать `/` и пробельные символы — значение
  используется в путях `ext/{extId}`.
</Info>

## Список грейдов

```
GET /saas/v2/staff/grade/list
```

Требуется аутентификация и право **«Просмотр персонала»** (`StaffView`).

<Info>
  Эндпоинт возвращает пагинированный список грейдов, упорядоченный по `order` — от младшего грейда к старшему.
  Параметры пагинации и фильтрации передаются как query-параметры.
</Info>

### Параметры

<ParamField query="skip" type="integer" required={false}>
  Количество пропускаемых записей (offset-пагинация). Минимум `0`.
</ParamField>

<ParamField query="take" type="integer" required={false}>
  Количество возвращаемых записей на странице. От `1` до `1000`.
</ParamField>

<ParamField query="page" type="integer" required={false}>
  Номер страницы (альтернатива `skip`). Минимум `1`.
</ParamField>

<ParamField query="gradeIds" type="integer[]" required={false}>
  Фильтр по ID грейдов. До 250 значений.
</ParamField>

<ParamField query="extIds" type="string[]" required={false}>
  Фильтр по списку внешних идентификаторов (`extId`). До 250 значений, каждое — максимум 50 символов.
</ParamField>

<ParamField query="positionId" type="integer" required={false}>
  Грейды, подходящие должности: её собственный список грейдов, а если у должности нет ограничения — все грейды
  школы.
</ParamField>

<ParamField query="search" type="string" required={false}>
  Поиск по названию грейда. Максимум 50 символов. Поиск нечёткий (находит и частичные совпадения), поэтому для
  поиска конкретного грейда по имени сравнивайте `name` найденных записей со своим значением без учёта регистра,
  а надёжнее — ищите по `extIds`.
</ParamField>

### Ответ

<ResponseField name="payload" type="object" required>
  Пагинированный объект: `items` (массив грейдов), `page`, `count`, `pages`, `isFirst`, `isLast`, `next`, `prev`.
</ResponseField>

## Создание грейда

```
POST /saas/v2/staff/grade/create
```

Требуется аутентификация и право **«Управление персоналом»** (`StaffManage`).

<Info>
  Новый грейд встаёт на вершину шкалы — получает наибольший `order` в школе. Чтобы поставить его на другое место,
  измените порядок в интерфейсе.
</Info>

### Параметры запроса

<ParamField body="name" type="string" required>
  Название грейда. От 1 до 100 символов. Пробелы в начале и конце обрезаются автоматически. Должно быть
  уникальным в рамках школы.
</ParamField>

<ParamField body="description" type="string | null" required={false}>
  Описание грейда — чем он отличается от соседних. До 500 символов. Пробелы в начале и конце обрезаются
  автоматически.
</ParamField>

<ParamField body="extId" type="string" required={false}>
  Внешний идентификатор грейда из системы клиента (CRM/1C). От 1 до 50 символов, не может содержать `/` и
  пробельные символы. Должен быть уникальным в рамках школы среди неудалённых записей.
</ParamField>

<RequestExample>
```bash cURL
curl --location 'https://api.exode.biz/saas/v2/staff/grade/create' \
  --header 'Seller-Id: {{ sellerId }}' \
  --header 'School-Id: {{ schoolId }}' \
  --header 'Content-Type: application/json' \
  --header 'Authorization: Bearer YOUR_TOKEN' \
  --data-raw '{
    "name": "Middle",
    "extId": "b7c1e9d2-4a3f-4e8b-9f61-2d0a5c7e3b18"
  }'
```

```javascript Node.js
const axios = require('axios');

async function createGrade() {

    },
    {
      headers: {
        'Seller-Id': '{{ sellerId }}',
        'School-Id': '{{ schoolId }}',
        'Content-Type': 'application/json',
        'Authorization': 'Bearer YOUR_TOKEN',
      },
    }
  );
  console.log(data.payload);
}

createGrade();
```

## Удаление грейда

```
DELETE /saas/v2/staff/grade/{gradeId}/delete
```

Требуется аутентификация и право **«Управление персоналом»** (`StaffManage`).

<Warning>
  Грейд нельзя удалить, пока он присвоен сотрудникам в открытых занятостях — вернётся
  `StaffGradeHasActiveEmployments`. Сначала смените сотрудникам грейд через
  [`promote`](/ru/exode-api/school/staff/employment) (параметр `toGradeId`) или уволите их.
</Warning>

<Info>
  При удалении грейд снимается со всех должностей, которым он был назначен, а его условия перехода удаляются.
  Готовность сотрудников к следующему грейду пересчитывается.
</Info>

### Параметры

<ParamField path="gradeId" type="integer" required>
  ID удаляемого грейда в рамках школы.
</ParamField>

### Ответ

<ResponseField name="affected" type="integer" required>
  Количество удалённых записей (`1` при успешном удалении).
</ResponseField>

<RequestExample>
```bash cURL
curl --location --request DELETE 'https://api.exode.biz/saas/v2/staff/grade/8/delete' \
  --header 'Seller-Id: {{ sellerId }}' \
  --header 'School-Id: {{ schoolId }}' \
  --header 'Authorization: Bearer YOUR_TOKEN'
```

```javascript Node.js

}
```
