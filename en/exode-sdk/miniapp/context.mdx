## MiniAppContext

The full context the host passes to the MiniApp during the handshake. It is returned from `app.init()` and available via `app.getContext()`.

```ts
interface MiniAppContext {
  user: MiniAppUser
  school: Record<string, unknown>
  theme: MiniAppTheme
  platform: Platform
  config: MiniAppConfig
  os?: 'ios' | 'android' | 'web'      // host 0.4+
  viewport?: MiniAppViewport          // host 0.4+
  capabilities?: MiniAppCapability[]  // host 0.4+
}
```

### MiniAppUser

<ResponseField name="id" type="number" required>
  The user's internal ID in Exode. For an unauthenticated visitor (a page with the
  "Available without login" option) it is `0`, and the other fields are empty.
</ResponseField>

<ResponseField name="uuid" type="string | null">
  The user's public UUID.
</ResponseField>

<ResponseField name="firstName" type="string | null">
  The user's first name.
</ResponseField>

<ResponseField name="lastName" type="string | null">
  The user's last name.
</ResponseField>

<ResponseField name="avatar" type="object | null">
  Avatar: `id` and links in three sizes, `small`, `medium`, `maximum` (each `string | null`).
</ResponseField>

<ResponseField name="email" type="string | null">
  The user's email.
</ResponseField>

<ResponseField name="phone" type="string | null">
  The user's phone number.
</ResponseField>

<ResponseField name="role" type="string" required>
  Role: `Student`, `Tutor`, `Parent`, etc.
</ResponseField>

<ResponseField name="language" type="string | null">
  Interface language: `en`, `ru`, `uz`, `qa`.
</ResponseField>

### MiniAppTheme

```ts
interface MiniAppTheme {
  scheme: 'light' | 'dark'
  accent?: string                       // host 0.4+: the school accent (CSS color)
  colors?: Partial<MiniAppThemeColors>  // host 0.4+: the host colors for the scheme shown
}

interface MiniAppThemeColors {
  background: string        // page background
  content: string           // cards and lists on the page
  elevated: string          // what floats over the page (menus, sheets)
  text: string
  textSecondary: string
  textTertiary: string
  accent: string
  accentForeground: string  // text and icons over the accent
  separator: string
  destructive: string
  positive: string
}
```

### MiniAppConfig

```ts
interface MiniAppConfig {
  isDesktop: boolean
  isMobile: boolean
  language: string
}
```

### Platform

```ts
type Platform = 'web' | 'native'
```

<Info>
  `native` means Exode is running inside a native shell (for example, an iOS/Android app). Otherwise it is `web`.
  A host 0.4+ passes the device system (`ios` / `android` / `web`) in the `os` field.
</Info>

### MiniAppViewport

Where the frame stands and what covers it (host 0.4+). Updated by the `viewport:changed` event.

```ts
interface MiniAppViewport {
  width: number                 // frame size, CSS px
  height: number
  safeArea: MiniAppInsets       // device safe area over the frame: status bar, notch, home indicator
  content: MiniAppInsets        // host chrome over the frame
  isEdgeToEdge: boolean         // the frame goes under the host chrome
  isFullscreen: boolean         // the frame covers the whole screen: no header, no bottom menu
  orientation: 'portrait' | 'landscape'
}

interface MiniAppInsets { top: number; right: number; bottom: number; left: number }
```

### MiniAppCapability

What the host can do for the app (host 0.4+): `popup`, `prompt`, `haptic`, `header`, `backButton`, `mainButton`,
`composer`, `composer.attachments`, `composer.voice`, `composer.dictation`, `composer.voiceOnly`,
`composer.dictation.audio`, `composer.voiceOnly.review`, `composer.voiceOnly.noCancel`, `fullscreen`, `orientation`,
`openLink`, `share`, `clipboard`. Check with `app.isSupported(capability)`; where each capability is available — on the
[Native look](/en/exode-sdk/miniapp/native#what-the-host-can-do) page.

### school

The `school` field contains the school's public data used by the Exode app itself (for example, `name`, `domain`,
`preferenceSettings`). The SDK types it as `Record<string, unknown>`: the set of fields is not fixed by the contract,
so check that the field you need is present before using it.

## Host events (MiniAppEventMap)

Sent by the host when data changes. The MiniApp subscribes via `app.on(event, handler)`.

| Event | Payload | When it fires |
|---------|---------|-------------------|
| `theme:changed` | `MiniAppTheme` | The user switched the theme |
| `user:updated` | `MiniAppUser` | The profile changed or the account was switched |
| `school:updated` | `Record<string, unknown>` | The school data changed |
| `config:updated` | `MiniAppConfig` | Window size or language changed |
| `route:changed` | `{ path, params }` | The host changed the route; `path` is the route template, for example `/course/:courseId([0-9_A-Za-z]+)` |
| `context:updated` | `Partial<MiniAppContext>` | Partial context update (reserved: the current host version does not send this event) |
| `visibility:changed` | `{ visible: boolean }` | The iframe became visible/hidden |
| `viewport:changed` | `MiniAppViewport` | The host chrome moved, the frame was resized, fullscreen was turned on, the screen rotated (host 0.4+) |
| `header:button` | `{ id }` | An item of the header "…" menu was pressed |
| `backButton:pressed` | — | "Back" was pressed while the app holds it |
| `mainButton:pressed` | — | The main button was pressed |
| `composer:submit` | `{ text, files, voice? }` | The composer was sent |
| `composer:voice` | `{ file, duration }` | A voice message was recorded (`File`, seconds) |
| `composer:change` | `{ text }` | Speech was heard in voice-only mode (`mic: 'dictation'`) |
| `composer:stop` | — | "Stop" was pressed while the field is `busy` |
| `composer:scrollDown` | — | The "scroll down" button above the field was pressed |

<Tip>
  The bridge applies the `theme:changed`, `user:updated`, `school:updated`, `config:updated`, `viewport:changed` and
  `context:updated` events to the context from `app.getContext()` itself; see
  [Getting the current context](/en/exode-sdk/miniapp/client#getting-the-current-context).
</Tip>

## MiniApp → host commands (MiniAppCommandMap)

Called via the `app.route` and `app.ui` namespaces, and since SDK 0.4 also `app.popup`, `app.haptic`, `app.header`,
`app.backButton`, `app.mainButton`, `app.composer` and `app.viewport`.

| Command | Payload | SDK method |
|---------|---------|-----------|
| `navigate` | `{ path, params? }` — `path` is the route template | `app.route.navigate()` |
| `navigate:back` | — | `app.route.back()` |
| `showSnackbar` | `{ message, type? }` | `app.ui.showSnackbar()` |
| `setTabbarVisible` | `{ visible }` | `app.ui.setTabbarVisible()` |
| `setHeaderVisible` | `{ visible }` | `app.ui.setHeaderVisible()` (no effect on custom pages yet) |
| `minimize` | — | `app.ui.minimize()` |
| `close` | — | `app.ui.close()` |
| `popup:show` | `{ title?, message, buttons? }` → `{ buttonId }` | `app.popup.show()`, `alert()`, `confirm()` |
| `popup:prompt` | `MiniAppPromptParams` → `{ value }` | `app.popup.prompt()` |
| `haptic` | `{ type, style? }` | `app.haptic.impact()`, `notification()`, `selection()` |
| `header:set` | `{ title?, left?, right? }` | `app.header.set()` |
| `backButton:set` | `{ visible }` | `app.backButton.show()`, `hide()` |
| `mainButton:set` | `{ visible, text?, disabled?, loading?, color?, textColor? }` | `app.mainButton.set()`, `hide()` |
| `composer:set` | `MiniAppComposerParams` | `app.composer.set()`, `hide()` |
| `composer:dismissKeyboard` | — | `app.composer.dismissKeyboard()` |
| `fullscreen:set` | `{ fullscreen }` → `{ isFullscreen }` | `app.viewport.requestFullscreen()`, `exitFullscreen()` |
| `orientation:lock` | `{ orientation }` | `app.viewport.lockOrientation()` |
| `orientation:unlock` | — | `app.viewport.unlockOrientation()` |
| `link:open` | `{ url, external? }` | `app.ui.openLink()` — `http`, `https`, `mailto`, `tel` only |
| `share` | `{ url?, text?, title? }` → `{ shared }` | `app.ui.share()` |
| `clipboard:write` | `{ text }` → `{ copied }` | `app.ui.copyText()` |

<Note>
  `minimize` collapses the app window and works only for pages with the
  "Floating window", "Side panel" or "Fullscreen" window type (see [Custom pages](/en/customization/custom-pages)).
  For the "Page" type the command does nothing. A collapsed window is not unloaded: the iframe stays alive,
  its state is preserved, and the app receives `visibility:changed` with `visible: false`.
</Note>

## BridgeMessage

The low-level `postMessage` message format. You usually do not need it, but it is useful for debugging.

```ts
interface BridgeMessage<T = unknown> {
  type: string
  requestId?: string
  payload?: T
  source: 'exode-host' | 'exode-miniapp'
}
```

<Warning>
  Do not send `postMessage` manually. All valid interactions go through the `ExodeMiniApp` methods: only they guarantee a correct handshake, requestId and origin validation.
</Warning>
