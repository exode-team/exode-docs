**type:** `QUERY_EXPORT_TYPE_SCHOOL_USER_FIND_MANY`

Exports the list of school users with profile data, contacts, access statuses and activity.

This is a report type for the [`query-export/generate`](/en/exode-api/school/query-export/generate) method: pass it
in the `type` field, and the fields described below in `variables`.

<Info>
  The `variables` structure mirrors the filter and sorting of the school user search.
  An unknown field or an invalid value is not ignored: the export finishes with
  `status: Failed`.
</Info>

---

### Variables (`variables`)

<ParamField body="filter" type="object" required>
  Filter parameters. Required: to export all records without filtering, pass an empty object `{}`.

  <Expandable title="filter properties">
    <ParamField body="userIds" type="integer[]">
      Filter by user IDs.
    </ParamField>

    <ParamField body="extIds" type="string[]">
      Filter by external identifiers (`extId`). Up to 250 values, each up to 50 characters.
    </ParamField>

    <ParamField body="search" type="string">
      Text search (name, email, phone, domain), up to 50 characters.
    </ParamField>

    <ParamField body="activated" type="boolean">
      Filter by the confirmed-login flag.
    </ParamField>

    <ParamField body="archived" type="boolean">
      Include archived users.
    </ParamField>

    <ParamField body="statuses" type="string[]">
      Filter by account statuses. An array of values: `Active`, `OnLeave`, `Banned`, `Blocked`,
      `Terminated`, `Deleted`. The filter has no `active`/`banned` fields; use `statuses` instead
      (for example, blocked users: `["Banned", "Blocked"]`). A request with `active` or `banned` finishes
      with `status: Failed`.
    </ParamField>

    <ParamField body="createdAtDateRange" type="object">
      Sign-up date range. The `from` and `to` properties are dates in ISO 8601 format.
    </ParamField>

    <ParamField body="lastOnlineAtDateRange" type="object">
      Last activity date range. The `from` and `to` properties are dates in ISO 8601 format.
    </ParamField>
  </Expandable>
</ParamField>

<ParamField body="sort" type="object">
  Sorting parameters. Values: `ASC` (ascending) or `DESC` (descending).

  <Expandable title="sort properties">
    <ParamField body="id" type="string">Sort by ID. `ASC` | `DESC`.</ParamField>
    <ParamField body="createdAt" type="string">Sort by sign-up date. `ASC` | `DESC`.</ParamField>
    <ParamField body="updatedAt" type="string">Sort by update date. `ASC` | `DESC`.</ParamField>
    <ParamField body="lastOnlineAt" type="string">Sort by last activity. `ASC` | `DESC`.</ParamField>
    <ParamField body="starsBalance" type="string">Sort by stars balance. `ASC` | `DESC`.</ParamField>
    <ParamField body="productAccessesCount" type="string">Sort by the number of product accesses. `ASC` | `DESC`.</ParamField>
  </Expandable>
</ParamField>

### Report columns

**SchoolUsers** sheet: User ID, First name, Last name, Login method, Phone number, Email, Telegram, Courses count,
Registration date, Registration type, Created by, Date of birth, Last login date. With `filter.archived: true`,
"Deleted at" and "Deleted by" are added.

Column names are given as they appear without the `Ux-Language` header (in English); with `Ux-Language: ru` the columns
are named in Russian (see [`generate`](/en/exode-api/school/query-export/generate) for details).

## Permission requirements

<Check>
  Token authentication and the [**"School User Management"**](/en/exode-api/permissions) permission (`SchoolManageUsers`) are required. Without the permission,
  the generation request succeeds, but the export finishes with `status: Failed`.
</Check>
