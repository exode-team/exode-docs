<Info>
    User states are key-value records in the database linked to a specific user.
    Reading and writing are available only for a limited list of keys (whitelist). Some keys are
    masked on read.

    The endpoints below work in the school context and require the school user management permission.

    Setting a value via PUT <u>fully replaces the key's previous value</u>.
    There are no partial updates (merge).
</Info>

## Supported keys

<AccordionGroup>
<Accordion title="UtmSignupParams">
  - Type: object.
  - GET/SET: yes/yes.
  - Masking: no.
  - Purpose: UTM/referral parameters of the first visit/sign-up.

  - <code>UtmSignupParams</code> is stored as an object of arbitrary string key-value pairs (for example, utm_source, utm_medium, fbclid).

  ```json Success (GET UtmSignupParams)
  {
    "success": true,
    "code": 200,
    "payload": {
      "value": {
        "fbclid": "EAA12xQ9YzGpKJ7tMoNybfBcGgGSsSixioGWZRcjvdAUCzvIjyGEXStvsIJC1wKj8ZpJ3kTn5Q2sL0mH7u9vW",
        "utm_term": "9876543210123456789",
        "utm_medium": "paid",
        "utm_source": "google",
        "utm_content": "creative_42_variant_b",
        "utm_campaign": "back_to_school_2025_ru"
      }
    }
  }
  ```

  ```json Body (SET UtmSignupParams)
  {
    "value": {
      "utm_source": "google",
      "utm_medium": "paid",
      "utm_campaign": "back_to_school_2025_ru",
      "utm_content": "creative_42_variant_b",
      "utm_term": "9876543210123456789",
      "fbclid": "EAA12xQ9YzGpKJ7tMoNybfBcGgGSsSixioGWZRcjvdAUCzvIjyGEXStvsIJC1wKj8ZpJ3kTn5Q2sL0mH7u9vW"
    }
  }
  ```
</Accordion>

<Accordion title="PersonalInfoFilled">
  - Type: boolean.
  - GET/SET: yes/yes.
  - Masking: no.
  - Purpose: flag indicating that personal information has been filled in.
  - <code>PersonalInfoFilled</code> is a boolean <code>true / false</code> value indicating whether personal information has been filled in.

  ```json Success (GET PersonalInfoFilled)
  {
    "success": true,
    "code": 200,
    "payload": {
      "value": true
    }
  }
  ```

  ```json Body (SET PersonalInfoFilled)
  {
    "value": true
  }
  ```
</Accordion>

<Accordion title="OnBoardingProgress">
  - Type: object.
  - GET/SET: yes/yes.
  - Masking: no.
  - Purpose: the user's onboarding progress.

  ```json Body (SET OnBoardingProgress)
  {
    "value": { "step": 3, "completed": false }
  }
  ```
</Accordion>

<Accordion title="ContentCategoryIds">
  - Type: array.
  - GET/SET: yes/yes.
  - Masking: no.
  - Purpose: content categories selected by the user (an array of IDs).

  ```json Body (SET ContentCategoryIds)
  {
    "value": [12, 45, 78]
  }
  ```
</Accordion>
</AccordionGroup>

<Info>
  Writing (`SET`) is allowed only for the keys `UtmSignupParams`, `PersonalInfoFilled`, `OnBoardingProgress`,
  `ContentCategoryIds`. Reading (`GET`) is additionally available for `VkToken` (returned **masked**).
  A request for a key outside this list returns a `400` error with `cause: "Unauthorized"` and the message
  `Not allowed key <key>` — this is a key restriction, not a token problem. A non-existent key name
  is rejected by validation (`400`).
</Info>

## Get a state by key

GET /saas/v2/user/:userId/state/get?key=PersonalInfoFilled

### Parameters

<ParamField path=":userId" type="integer" required>
The user's numeric ID in Exode (the `id` field from [`user/find`](/en/exode-api/school/user/find) or
[`user/list`](/en/exode-api/school/user/list)). The user must belong to the school from the `School-Id` header.
</ParamField>

<ParamField query="key" type="string" required>
State key — one of the values from the [list above](#supported-keys), case-sensitive.
</ParamField>

### Response

<ResponseField name="value" type="any" required>
The state value. If no value has been written for the key yet, `null`.
</ResponseField>

## Set a state by key

PUT /saas/v2/user/:userId/state/set?key=PersonalInfoFilled

### Parameters

<ParamField path=":userId" type="integer" required>
The user's numeric ID in Exode (the `id` field from [`user/find`](/en/exode-api/school/user/find) or
[`user/list`](/en/exode-api/school/user/list)). The user must belong to the school from the `School-Id` header.
</ParamField>

<ParamField query="key" type="string" required>
State key — one of the values from the [list above](#supported-keys), case-sensitive.
</ParamField>

<ParamField body="value" type="any" required>
The value to write to the state. Its type depends on the key.
</ParamField>

### Response

<ResponseField name="set" type="boolean" required>
Flag indicating that the state was written successfully.
</ResponseField>

## Permission requirements

<Check>
Requires token authentication and the [**"School User Management"**](/en/exode-api/permissions) permission (`SchoolManageUsers`).
</Check>
