<Tip>
  This operation removes multiple users from a group at once.
</Tip>

<Warning>
    When members are removed from a group, the system automatically checks their product accesses:

    -> If the user remains a member of other groups with the same product, the access is kept.

    -> If the user is no longer a member of any group with this product, the access is fully deactivated.
</Warning>

<HeaderParamFields/>

```
DELETE /saas/v2/group/:groupId/member/delete-many
```

Requires authentication and the [**"School User Management"**](/en/exode-api/permissions) permission (`SchoolManageUsers`).

## Request parameters

<Tip>
  The maximum number of users you can remove in one request is 250. To remove more
  users, use several requests.
</Tip>

<ParamField path="groupId" type="integer" required>
  Group ID: the `groupId` field from the [group list](/en/exode-api/school/group/list).
</ParamField>

<ParamField body="userIds" type="integer[]" required>
  Array of numeric Exode user IDs (not the member record IDs `id` from the
  [member list](/en/exode-api/school/group-member/list), but their `userId`). Up to 250 users per
  request.
</ParamField>

<Info>
  If a user is not a member of the group, they are ignored. The response contains the number of
  members actually removed.
</Info>

## Response parameters

<ResponseField name="affected" type="integer" required>
  Number of group members actually removed. Users who were not members of the group are not counted in
  this number.
</ResponseField>

## Interaction with automatic assignment

<Warning>
  Removal via the API is considered **manual** and blocks subsequent automatic assignment: for each removed
  user, an exclusion is created with the reason "removed from the group manually". Assignment rules based on the org structure will no longer
  add the user back to this group.

  Exclusions are created only for corporate groups that have automatic assignment configured. To lift
  the block, add the user back via
  [adding members](/en/exode-api/school/group-member/create-many); this clears the exclusion.
</Warning>

<Note>
  If you synchronize group membership from an external system (for example, from 1C), keep this in mind for regular exports:
  removing a member in one synchronization iteration permanently excludes them from automatic assignment until they
  are added back via the API.
</Note>

## Permission requirements

<Check>
  Removing members from a group requires the **"School User Management"** permission (`SchoolManageUsers`).
</Check>

<Warning>
  The service user must be authenticated with a token and have the appropriate access rights to the specified
  school.
</Warning>
